# H98 虚拟公司功能验证

验证顺序为：启动检查 → 统一登录 → 各系统基本操作 → 跨系统联动 → 招聘入职。
本文是手工验收步骤，不代表本次已重新执行全部业务测试。

验证对象为 `examples/H98_virtual_company`，包含统一身份认证、ERP/人事、
网盘、工作聊天、项目、知识库、工单和资产管理，不包含 Agent、邮箱、银行和支付。

## 账号与访问地址

为不同角色使用不同的浏览器配置文件，避免登录状态相互覆盖。
普通员工在应用登录页选择 **Company**；项目和工单网站会自动跳转到公司登录。

| 身份 | 公司登录账号 | 初始密码 | 主要职责 |
| --- | --- | --- | --- |
| Alice | `EMP0001` | `EmployeeDemo123!` | 主管、审批、采购、库存、销售、面试 |
| Bob | `EMP0002` | `EmployeeDemo123!` | 普通员工、自助申请 |
| Carol | `EMP0003` | `EmployeeDemo123!` | 人事和财务 |
| 管理员 | `admin` | `IdentityAdminDemo123!` | 公司登录及应用管理 |

| 系统 | 浏览器地址 |
| --- | --- |
| 统一身份认证 | http://localhost:8085/realms/company/account/ |
| 身份管理后台 | http://localhost:8085/admin/ |
| ERP | http://localhost:8082/app |
| 人事 | http://localhost:8082/hrms |

| 工作聊天 | https://chat.localhost:8086 |

聊天使用自签名 HTTPS，首次访问需要接受证书。仿真内部域名由仿真网络解析；
宿主机浏览器使用上述映射地址。

必要时可以使用应用原生管理账号：

| 系统 | 原生账号 | 密码 |
| --- | --- | --- |
| ERP / 人事 | `Administrator` | `ERPAdminDemo123!` |

| 工单后台 | `glpi` | `HelpdeskAdminDemo123!` |

网盘原生登录入口为 `/login?direct=1`。项目和工单的浏览器入口仍由公司登录保护。
各应用保留各自的业务权限，公司登录不等于所有员工拥有相同权限。

## 1. 检查启动是否完成

在 H98 的 `output` 目录执行：

```sh
docker compose ps -a
```

检查长期运行的应用、数据库、工作进程和同步进程是否正常运行。
名字以 `-initialize` 结尾的初始化容器完成后显示 `Exited (0)` 属于正常情况。
初始化未完成时，先不要提交业务单据。

如果初始化失败，查看对应服务日志，例如：

```sh
docker compose logs --tail=100 company-erp-initialize
docker compose logs --tail=100 company-identity-initialize
```

然后逐个打开上表中的网站，在网络地图中查看公司 AS164 的部门、应用、数据和分支网络。

**通过标准：** 应用页面能打开，初始化完成，长期运行服务没有反复退出。

## 2. 验证统一登录

1. 用 Bob 登录统一身份认证的个人账户页面。
2. 在同一个浏览器配置文件中依次访问 ERP、网盘、聊天、项目、知识库和工单。
3. 应用提供登录选项时选择 **Company**，检查公司登录会话能否复用。
4. 检查显示的用户是否为 Bob，邮箱是否为 `bob@company.com`。
5. 分别用 Alice 和 Carol 重复上述检查。

首次进入聊天时，按界面提示确认邮箱可见性。

**通过标准：** 同一公司账号可以进入各应用，身份、邮箱对应正确，登录会话能够复用。

## 3. 验证日常协作

| 系统 | 操作 | 检查结果 |
| --- | --- | --- |
| 聊天 | Bob 在 `general` 频道发送消息，Alice 回复；再互发私信 | 双方能看到正确的消息及发送者 |
| 网盘 | Bob 上传一个文件并分享给 Alice | Alice 能打开或下载，内容一致 |
| 知识库 | Carol 创建“员工手册”及一个页面，Bob 打开并编辑 | 修改能够保存和查看 |
| 项目 | 在 `Company Operations` 中创建任务、指定负责人、添加评论并修改状态 | 成员看到同一条任务及其最新状态 |

这些操作分别验证各应用自身的功能。网盘文件不会自动成为知识库附件，
各应用之间的业务对象也不会因为使用统一登录就自动互通。

**通过标准：** 不同员工能协作处理相同的消息、文件、页面和任务。

## 4. 验证工单和资产

1. Bob 提交“电脑无法开机”的工单，填写问题描述。
2. 公司管理员找到工单，回复、分配处理人员并记录处理结果。
3. Bob 查看回复和处理状态。
4. 管理员新增一台测试电脑，填写资产编号并关联给 Bob。
5. 检查设备使用人和资产信息。

**通过标准：** 员工与管理员看到同一条工单及其处理过程；资产能关联到正确员工。

ERP 采购入库的电脑目前不会自动进入工单系统资产库，该联动不属于本轮通过条件。

## 5. 验证员工资料和请假审批

Carol 在 ERP/人事中查看初始员工：

- 工号、姓名、邮箱、部门正确。
- Bob 的主管为 Alice。

然后完成：

```text
Bob 申请一天年假 → Alice 审批 → Bob 查看审批结果和假期余额
```

选择当前年度内未来的工作日，假期类型使用 `Annual Leave`。
全新环境初始年假为 20 天；已有业务数据时，以操作前后的余额变化为准。

**通过标准：** Alice 可以审批 Bob 的申请，审批后假期余额变化与申请天数相符。

## 6. 验证报销和聊天通知

完成以下流程：

```text
Bob 提交差旅报销 → Alice 审批并提交 → Carol 处理付款记账
```

建议使用一笔 USD 100 的报销：

| 字段 | 值 |
| --- | --- |
| 报销类型 | `Travel` |
| 成本中心 | `Main - EC` |
| 审批金额 | 填写实际核准金额 |

Alice 审批并提交后，检查聊天的 `finance` 频道、`Expense approvals` 主题。
核对通知中的员工、报销单号和金额。

**通过标准：** 报销单状态与金额正确，聊天中出现对应通知，财务可以记录付款。

这里的付款属于 ERP 内部记账，H98 没有连接外部银行或支付系统。

## 7. 验证采购、库存、销售和财务

使用初始化好的供应商、客户和商品，先采购两台电脑，再销售一台。

| 字段 | 示例值 |
| --- | --- |
| 供应商 | `Company Hardware Supplier` |
| 客户 | `Company Customer` |
| 商品 | `COMPANY-LAPTOP` |
| 仓库 | `Stores - EC` |
| 已配置采购/销售单价 | USD 800 |

Alice 处理采购、库存和销售，Carol 处理财务记录。
在原单据上继续创建后续单据，保留它们之间的关联。

```text
采购订单 → 收货 → 采购发票 → 付款记录
             ↓
          库存增加
             ↓
销售订单 → 发货 → 销售发票 → 收款记录
```

**通过标准：** 收货后库存增加 2，发货后减少 1，最终比测试前多 1；
发票、应收应付和收付款记录能关联到对应业务单据。

公司初始资金为 ERP 账簿中的 USD 100,000，实际余额会随着之前的业务操作变化。

## 8. 验证工资计算

Carol 为 Bob 创建 `Salary Slip`，选择适用月份和
`Company Monthly Salary` 工资结构，计算并提交。

检查员工、月份、基本工资和计算结果。初始员工月基本工资为 USD 5,000，
实际计算结果还应结合适用日期、出勤和请假等设置检查。

**通过标准：** 工资单能够生成、计算并提交。

本轮先验证工资计算；完整发薪和绩效考核完成流程尚未做端到端验证。

## 9. 验证员工信息跨系统同步

1. 在 ERP 的 Bob 员工记录中，把名字临时改为 `Bob Test`，工号和邮箱保持不变。
2. 等待一个同步周期，通常约 30 秒。
3. 查看统一身份认证、网盘、聊天、项目、知识库和工单中的用户姓名。
4. 必要时刷新或重新登录，排除页面缓存。
5. 检查原来的文件、任务、工单和消息仍然属于同一个账号。
6. 完成后把名字改回去。

**通过标准：** 各应用姓名更新，稳定工号仍为 `EMP0002`，没有因为改名重复创建账号。

员工资料以 ERP 的 Employee 为来源，应在该记录上修改，而不是分别维护各应用资料。

## 10. 验证完整招聘入职

前面流程通过后，再验证下面的长流程。使用一个尚未占用的新工号，
例如 `EMP0004`，不需要修改 JSON、重新编译或重启世界。

| 顺序 | 操作者 | 操作 |
| --- | --- | --- |
| 1 | Carol | 准备 Skill 和 Interview Round，配置技能要求并指定 Alice 为面试官 |
| 2 | Carol | 创建 Job Opening，选择职位和部门，启用 Publish |
| 3 | 候选人 | 打开 http://localhost:8082/jobs ，选择职位并通过 Apply Now 提交申请 |
| 4 | Carol | 为候选人设置职位，创建并安排 Interview |
| 5 | Alice / Carol | Alice 提交 Interview Feedback，Carol 提交通过的面试结果 |
| 6 | Carol | 提交 Job Offer，并把候选人的答复记录为 Accepted |
| 7 | Carol | 创建 Employee Onboarding，关联申请人和录用通知，设置假日日历、活动、负责人和必做事项，再提交 |
| 8 | 活动负责人 | 完成分配给自己的 ERP Tasks；检查必做事项未完成时不能提前创建员工 |
| 9 | Carol | 在入职单选择 Create → Employee，填写新工号、姓名、部门、主管及必填日期等资料 |
| 10 | ERP 管理员 | 在 Employee 中填写 Company Email，选择它为 Preferred Contact Email，保存并点击 Create User |
| 11 | Carol | 为新员工提交 Leave Allocation 和 Salary Structure Assignment |
| 12 | 新员工 | 等待同步，用新工号和 `EmployeeDemo123!` 登录 Company，按提示修改临时密码，再访问各应用 |
| 13 | Carol | 检查入职单关联的新员工和完成状态，关闭招聘职位 |

管理员可以提前创建 Employee Onboarding Template，HR 也可以直接填写入职活动。
入职事项生成的是 ERP 自己的 Tasks，与独立项目管理网站分别管理。
公司邮箱在员工账号关联前可以编辑，关联后只读。

**通过标准：** 公开申请、面试、录用、必做入职事项、员工创建、公司账号开通和
各应用登录能够连续完成，稳定工号贯穿各系统。

录用通知的接受结果由 HR 记录；H98 尚未配置公司邮件投递和候选人电子签署。

## 记录验证结果

每项记录操作者、单据编号、预期结果和实际结果即可。
失败时优先查看该应用及其初始化服务的日志；身份同步问题再查看
`company-identity-directory` 日志。

停止环境使用 `docker compose down`。重建镜像不会自动清空业务数据；
重新编译不带 `--state` 才会生成新的应用状态目录。

部署和构建方法见 [H98 README](../examples/H98_virtual_company/README.md)。
