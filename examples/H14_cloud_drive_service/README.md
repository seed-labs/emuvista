# H14: Agents Using Cloud Drive

This example uses one Cloud service, the Alice and Bob containers, and the same demo profile throughout two demonstration stages. First, the agents log in, upload and share a file, and verify its download. Then, Claw is enabled to demonstrate autonomous collaboration driven by Cloud events.

## Prerequisites

Use Linux Docker Engine, Docker Compose v2+, Python 3.10+, and a linux/amd64 environment. At least 4 vCPUs and 8 GB of available memory are recommended. Run the following commands from examples/H14_cloud_drive_service in the repository:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
docker build --platform linux/amd64 -f ../../docker-images/deepseek-harness/Dockerfile.dsh-runtime -t seedemu-dsh-runtime:0.2.0-rc.2 ../../docker-images/deepseek-harness
```

requirements.txt installs a pinned SEED source commit in editable mode to retain the service templates required at runtime. Build the shared image on first use or when upgrading it. For build proxy configuration, see the [shared image documentation](../../docker-images/deepseek-harness/README.md).

Run commands from this example directory in each terminal. Before using Python in a new terminal, activate the virtual environment with source .venv/bin/activate.

## Start the Topology

After completing the prerequisites, run:

```bash
python CloudDriveTopology.py
cd output
docker compose -p emuvista-h14 build 072d7840db6a44d06e5c5fd4d7ea8a7d ad739b7b201eccafa592110d2bf214a7
docker compose -p emuvista-h14 build
docker compose -p emuvista-h14 up -d
docker compose -p emuvista-h14 ps
cd ..
```

The two hash names identify base image services generated by the current SEED version. Building them first prevents missing base image errors on the initial build. The topology script only generates deployment configuration; the commands above build and start the containers manually. Plugin source code and dependencies are prepared during the image build.

Container startup automatically creates missing Cloud accounts and DSH profiles, installs the local bundle, and applies the default preset. Existing accounts, passwords, and profiles are preserved. Wait until Cloud, Alice, and Bob are healthy in the ps output before starting DSH manually. If they are still starting, check again later. If initialization fails, inspect docker compose -p emuvista-h14 -f output/docker-compose.yml logs --tail 50 and the affected container's /var/log/h14-initialize.log.

## Open the Agents

Open two terminals in this example directory and start Alice and Bob manually.

Alice:

```bash
docker compose -p emuvista-h14 -f output/docker-compose.yml exec hnode_154_alice dsh --profile demo --no-open
```

Bob:

```bash
docker compose -p emuvista-h14 -f output/docker-compose.yml exec hnode_154_bob dsh --profile demo --no-open
```

In a third terminal on the Docker host, start the container Web tunnel. This is the example's standard access method because DSH listens on the loopback address inside each container:

```bash
python container/web_tunnel.py
```

| Agent | Address on the Docker host |
| --- | --- |
| Alice | http://127.0.0.1:18081 |
| Bob | http://127.0.0.1:18082 |

Use the authentication URL printed in each DSH terminal. Replace port 3080 with 18081 for Alice or 18082 for Bob, keeping the authentication token intact. Configure the model API endpoint, credentials, and model in the Web settings. A browser on the Docker host can access these addresses directly. If the browser is on another machine, establish an SSH tunnel to the Docker host, forwarding local ports 18081 and 18082 to the corresponding loopback ports on that host.

## Log In, Upload, Share, and Download

Create a new session in each Web interface and select **EmuVista Cloud Agent**:

1. Send Alice the [upload and share prompt](prompts/phase1/alice.md). Wait for the upload and read-only share to complete, and record the returned shareId and SHA-256.
2. Insert the shareId into the [download and verification prompt](prompts/phase1/bob.md), then send it to Bob.
3. Inspect the actual tool results in Trajectory. Bob should download the exact text Hello Bob from Alice through Cloud Drive. and return the same SHA-256 as Alice's upload.

| Agent | Expected Cloud interactions |
| --- | --- |
| Alice | cloud_login → cloud_upload → cloud_share, with bob as the recipient and read permission |
| Bob | cloud_login → cloud_list_shares → cloud_download, locating the matching share and verifying its content and hash |

The accounts are alice / alice-password and bob / bob-password. The Cloud URL is https://cloud.seedvista.test. A new demo profile initially installs only the Cloud bundle; each agent completes one user task and then stops. Existing profiles are preserved. If an existing profile already includes Claw, stop DSH and run `dsh plugin --profile demo remove @emuvista/dsh-claw-bundle` inside each agent container before repeating stage one.

The linked prompt files are currently in Chinese. Copy their prompt text and replace the indicated placeholders before sending.

## Autonomous Collaboration Driven by Cloud Events

After stage one, stop both DSH processes while keeping the Cloud container and Web tunnel running. Install the Claw bundle in the same demo profile:

```bash
docker compose -p emuvista-h14 -f output/docker-compose.yml exec hnode_154_alice dsh plugin --profile demo add /opt/emuvista/agent-plugins/claw-bundle
docker compose -p emuvista-h14 -f output/docker-compose.yml exec hnode_154_bob dsh plugin --profile demo add /opt/emuvista/agent-plugins/claw-bundle
```

The images already contain Claw, so no topology or image rebuild is required and no additional profile is created. Skip installation if the bundle is already installed. If it was previously disabled, enable it again in Web Plugins. Restart DSH with the commands under “Open the Agents,” create new sessions, and select **EmuVista Cloud Agent**:

1. Send Bob the [stage two preparation prompt](prompts/phase2/bob.md). Wait for login and the incoming-share baseline check to complete.
2. Send Alice the [stage two initiation prompt](prompts/phase2/alice.md), replacing the unique identifier placeholder for this run. Alice creates a new conversation file and shares it with read/update permissions.
3. Send no further manual prompts. Observe both agents being awakened by Cloud shares and file changes, producing seven alternating messages before stopping.

Stage two uses a new file distinct from stage one. Each reply must use expected_etag for a safe update. Inspect the emuvista-claw event source, tool calls, and final file in Trajectory. Both stages demonstrate actual agent use of Cloud; the second also shows how service events trigger subsequent actions.

## Shut Down

Press Ctrl+C in both DSH terminals and the tunnel terminal, then run:

```bash
docker compose -p emuvista-h14 -f output/docker-compose.yml down --remove-orphans
```

Cloud data and DSH profiles remain in .runtime. After starting the containers again, manually start both agents and the tunnel.
