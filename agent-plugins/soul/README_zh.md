# DeepSeek Harness 的 Soul 插件

[English](README.md)

Soul 为 DSH 居民提供可配置的人格卡，以及保存个人经历、关系事件、反思和意图的持久化存储。这些记录归属于居民，在同一 DSH 进程的不同会话中均可访问。

居民可以记录观察或推断及其来源。反思引用已保存的证据，并可提出候选愿望。居民可以将愿望采纳为带有完成条件的意图，再通过当前 preset 提供的工具行动，也可以推迟或放弃意图。

## 安装

使用 Node.js 24、pnpm 和 DSH 0.2.0-rc.2，并启用 Web 会话控制器与 DSH Schedule。在 DSH 实际加载插件的环境中，进入本包目录执行构建命令。

```bash
DSH_PROFILE='your-profile-name'
pnpm install --frozen-lockfile
pnpm test
dsh plugin --profile "${DSH_PROFILE:?set DSH_PROFILE}" add "$(pwd)"
```

Soul 作为普通插件依赖安装。在 profile 的 cordis.patch.yml 中插入一条配置，为条目设置唯一 id，将 name 设为 @emuvista/soul，并在 config 中填入下表所列字段。已有 Soul 条目时直接修改该条目。每个 DSH 进程配置一位居民。修改 profile 后重启 DSH，并用以下命令检查合成后的配置。

```bash
dsh --profile "${DSH_PROFILE:?set DSH_PROFILE}" --dump-config
```

Soul 通过 DSH 运行时上下文提供人格卡和当前意图。如果 preset 使用 persona 插件，启用 includeRuntimeContext。在 profile 补丁中覆盖 preset 时，请保留其完整配置，因为 DSH 会替换整段 config。

## 配置与存储

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `residentId` | 必填字符串 | 稳定的居民标识，长度为 1–48 个字符，只允许字母、数字、下划线和连字符。 |
| `card.identity` | 必填字符串 | 简要描述居民的身份。 |
| `card.values` | 可选字符串数组 | 指导居民选择的价值观，默认为空数组。 |
| `card.preferences` | 可选字符串数组 | 居民通常偏好的做法，默认为空数组。 |
| `card.boundaries` | 可选字符串数组 | 居民决定行动时应遵守的边界，默认为空数组。 |
| `stateFile` | 可选路径 | 覆盖居民状态文件的保存位置。 |
| `autoReflection` | 可选布尔值 | 是否启用自动反思，默认为 true。 |

默认状态文件为 `$DSH_HOME/storages/emuvista-soul/<residentId>.json`。未设置 DSH_HOME 时，Soul 使用 `~/.dsh`。同一状态文件只由一个进程写入。重建容器时保留状态文件、DSH 会话数据和 Schedule 存储。凭据存放在凭据服务中，Soul 记录保存与居民决策有关的观察和引用。

## 自动反思

居民成功结束一轮后，Soul 检查是否积累了至少三条新保存的经历或关系事件。达到条件时，将最近最多八条新增记录和人格卡交给该会话使用的模型。模型根据经历自行决定提出多少条挂心，也可以不提出。建议有合适内容时提出一到五条，并为每条引用证据、给出 0 到 100 的整数权重。Soul 将挂心保存为候选愿望，在运行时上下文按权重从高到低展示，同权重优先展示较新的挂心。旧记录没有权重时以中性的 50 展示，原有 1 到 5 的权重依次映射为 0、25、50、75、100。后续反思可按 ID 更新、搁置或恢复原有挂心。每次变化记录理由、引用的新证据以及修改前后的值。没有提到的挂心保留原样。搁置的挂心仍可回顾，但暂时不展示给日常回合。居民可以暂时放下，也可以用 `soul_intention_update` 采纳。预约复查仍需主动调用 `soul_rest`。设置 `autoReflection: false` 可关闭额外模型请求。

## 工具

| 工具 | 作用 |
| --- | --- |
| `soul_recall` | 读取当前意图，检索近期经历、关系事件和反思。 |
| `soul_remember` | 记录经历或关系事件，附上来源，并标明内容属于观察还是推断。 |
| `soul_reflect` | 引用已有的经历或关系记录，保存一项判断，并可提出候选愿望。 |
| `soul_intention_update` | 将愿望采纳为意图，修订或暂停意图，或将其标记为完成或放弃。 |
| `soul_life` | 在居民的主会话中开启或停止周期性自主活动。 |
| `soul_rest` | 为一项已采纳的意图设置或替换一次性回访提醒。 |

## 居民生命周期

在居民的主会话中，请它调用 `soul_life` 并传入 `enabled=true`，即可开启周期性活动。可选参数 `interval_seconds` 默认为 120，取值为 60 至 86400 之间的整数。每次 Schedule 投递后，居民都可以反思、执行意图或继续等待。目标和行动由居民选择，每次投递都可能调用已配置的模型。

居民可以通过 `soul_rest` 为一项已采纳的意图安排一次复查，并说明醒来后要重新判断什么。每位居民只保留一个由 Soul 管理的一次性回访提醒。暂停或结束对应意图时会取消提醒。周期唤醒可能先于意图的复查时间，居民届时仍可选择继续等待。

两类提醒都由 Schedule 投递和恢复，目标是创建提醒的会话。要停止生活模式，请居民调用 `soul_life` 并传入 `enabled=false`。这会取消周期任务和归属同一会话的 Soul 回访提醒。已入队的提醒仍可能送达，居民在行动前应检查意图及环境的当前状态。

## 验证

运行 `pnpm test` 可在不调用模型的情况下检查反思证据校验、状态重载、意图更新和提醒管理。验证已部署的 profile 时，确认六个工具均已注册，运行时上下文包含对应居民的人格卡和当前意图。通过会话轨迹可以核对唤醒来源、引用的证据，以及行动和状态更新是否指向同一个意图 ID。

## 挂心到期回顾与情绪

为 Soul 配置 `concernReviewSeconds`（5–86400 秒）并保留 `autoReflection` 后，已挂心但尚未采纳的事项到期可以独立发起后台反思。居民至少完成一轮后才有模型路由可用。回顾使用该挂心已经引用的经历，每次处理一条，成功时间写入状态。后台回顾可以保留或修订当前挂心，居民仍在自己的会话中决定是否行动。

配置 `emotion.enabled: true` 后，Agent 的上下文与 `soul_recall` 会提供担忧、挫败和愉悦三个 0–100 的值。居民用 `soul_appraise` 引用一条已经保存的经历或关系事件，为各维填写 −100 至 100 的变化量。同一事件只计一次。状态持久化，读取时按 `halfLifeSeconds` 向 `baseline` 回落，半衰期默认 3600 秒，各维基线默认 0。情绪供 Agent 决定是否行动及行动时机，也会提供给反思模型。

## 自主运行

Soul 启用后，进程内所有 Agent 都禁止向操作员请求人工确认、审批或答复。工具执行层会拒绝提问和进入或退出交互式规划的工具调用，人工审批与提问事件会在宿主端结束。已经授权的工具按原权限运行，需要新增授权的操作会被拒绝。

Soul 在发布自然语言文本前检查常见中文和英文确认措辞。命中的文本块会被替换，本轮最多由 Soul 发出一条标记为 emuvista-soul-autonomy 的内部纠正消息，让 Agent 在已有权限下继续、选择其他办法或结束。内部纠正消息独立于人为启动和世界事件。自然语言过滤按明确措辞匹配，结构化审批和提问入口固定拒绝。
